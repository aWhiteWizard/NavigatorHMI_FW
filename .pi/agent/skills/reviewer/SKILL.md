# 代码审查员（Reviewer）

三层代码审查，逐层检查，输出结构化审查报告。

## 审查框架（严格执行顺序）

### 第一层：通用（所有语言必检）

1. **逻辑正确性**：边界条件（空输入/0/MAX/负数）、循环终止、返回值是否被忽略
2. **安全性**：缓冲区溢出、注入风险、权限检查、路径遍历
3. **可读性**：命名是否表意、函数是否过长（>50 行提醒）、关键路径有注释
4. **性能**：不必要的内存分配、热循环里的 I/O、冗余拷贝

### 第二层：语言特化（按被审文件语言）

**C#**：
- `using` 块 / `IDisposable` 是否遗漏
- `async void` 只用于事件处理器，其余用 `async Task`
- `ConfigureAwait(false)` 在库代码中使用
- LINQ 多次枚举（`.Count()` 后遍历 → 改 `ToList()`）

**C++**：
- RAII：原始 `new`/`delete` → 改 `unique_ptr`/`make_unique`
- 虚析构：有虚函数的基类析构必须 `virtual`
- 三/五法则：自定义了析构/拷贝构造/赋值任一，另外几个也要定义或 `=delete`
- 悬空引用：返回局部变量的引用、iterator 失效
- Qt：信号槽 sender/receiver 生命周期、QObject 父对象 delete 链、跨线程信号

**C**：
- `malloc`/`free` 配对（每个 `malloc` 找到对应 `free`）
- 数组越界（循环索引、差一错误）
- 指针 NULL 检查（每个参数、返回值）
- ISR 安全：不调 `printf`/`malloc`/`sleep`、`volatile` 修饰共享变量
- 整数溢出：中间计算结果类型是否够大

**Python**：
- 裸 `except:` → `except Exception as e:`
- 可变默认参数 `def f(x=[]):`
- 文件/连接未用 `with`
- 大循环里用 `.format`/f-string 而不用 `%` 拼接

### 第三层：嵌入式特化（C/C++/固件代码必检）

- **中断安全**：ISR 是否极短、是否关中断后做耗时操作
- **内存约束**：栈深度估计（递归风险）、堆碎片风险、`malloc` 返回值检查
- **实时性**：最坏执行时间是否可能超 deadline
- **硬件交互**：MMIO 寄存器 `volatile`、memory barrier (DSB/DMB)、bit-banding 原子性
- **看门狗**：大循环/长时间操作里有没有喂狗

## 审查报告格式

```
## 审查结果: [通过 / 有条件通过 / 需要修改]

### 🔴 必须修改 (会导致 bug/安全问题)
- [文件:行] 问题描述 + 建议修改

### 🟡 建议修改 (代码质量/性能)
- [文件:行] 问题描述 + 建议

### 🟢 通过项
- 无问题的检查项列表

### 📝 备注
- 其他观察
```
