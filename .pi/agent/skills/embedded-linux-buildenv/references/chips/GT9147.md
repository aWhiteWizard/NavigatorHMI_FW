# GT9147 电容触摸 IC

> 数据手册: `GT9147数据手册.pdf` + `GT9147编程指南.pdf`
> 驱动例程: `Linux驱动例程/23_multitouch/gt9147.c`

## 基本参数

| 项目 | 值 |
|------|-----|
| I2C 地址 | `0x14`（INT 拉低复位）或 `0x5D`（INT 悬空复位） |
| I2C 总线 | I2C2（UART5_TXD/RXD 复用，`/dev/i2c-1`） |
| INT 引脚 | GPIO1_IO09 |
| RST 引脚 | GPIO5_IO09（SNVS_TAMPER9） |
| 寄存器地址 | 16 位 |
| 状态寄存器 | `0x814E`（bit7=buffer status, bit3-0=touch count） |
| 坐标数据 | `0x814F` 起，每个触摸点 5 字节（TrackID + X2 + Y2） |
| 配置表 | 184 字节 @ `0x8047`，校验和 @ `0x80FF` |
| Config Fresh | `0x8100 = 0x01` |

## 兼容的主线驱动

| 驱动 | 路径 | OF 匹配 | GT9147 支持 |
|------|------|---------|------------|
| `goodix.c` | 4.1.15 主线 | 无 gt9147 | ❌ 需补 OF 表 + 坐标地址错(0x8157 vs 0x814F) |
| `gt9147.c` | 正点原子官方 | `goodix,gt9147` | ✅ |
| GTP V2.4 | 原厂系统（Yocto） | 无、I2C 直探 0x5D | N/A（未验证成功） |

## 调试踩坑记录

### 1. GPIO active-low 陷阱
`devm_gpiod_get(..., GPIOD_OUT_HIGH)` + `gpiod_set_value(rst, 0)`：
- 对于 active-low GPIO：`set_value(0)` = deassert（**释放**复位），不是 assert！
- 正点原子 gt9147.c 用 `gpio_set_value`（raw 电平），不是 `gpiod_set_value`（逻辑电平）
- 修复：`gpiod_set_value(rst, 1)` 才是拉低复位

### 2. 坐标地址 0x8157 vs 0x814F
数据手册 PDF 转文本时行乱码导致坐标地址被误读为 `0x8157`。
正确地址是 `0x814F`（正点原子官方驱动用 `GT_TP1_REG = 0x814F`，已上板验证）。

### 3. 每触摸点 5 字节 vs 8 字节
GT9147 每个触摸点 5 字节（TrackID + X2 + Y2），不是主线 goodix.c 用的 8 字节（含 Size 字段）。直接用主线驱动的 `goodix_ts_report_touch` 会有 Size 越界读。

### 4. 配置表校验和
必须写到 `0x80FF`，否则芯片不认。`writecfg` 工具写 186 字节（`{0x80,0x47}` 地址前缀 + 184 字节配置），但不含校验和。需额外 `i2cwrite 0x14 0x80FF 0x2B`。

### 5. 冷启后芯片 ID 不稳定
冷启后 `0x8140` 首字节在 `0x10`~`0x98` 间随机变化 → 内部 flash 损坏或固件丢失。稳定的芯片每次应返回相同的 config version。

### 6. ISR 风暴与驱动选择
- 主线 `goodix.c`：ISR 疯狂触发（百万级），`end_cmd` 对 GT9147 无效
- 正点原子 `gt9147.c`：ISR 正常（千级），使用 Edge 触发，写 `0x00` 到 `0x814E` 正确清除中断

### 7. 硬件故障判定
`GSTID` 永远 `0x00` + 中断在涨 + 所有软件修复无效 + 原厂系统同样失败 → 触控传感器物理失效。不是驱动问题。
